# 真实面试链路验证（2026-11-02）

## 最新浏览器全流程验收

本轮在专用 `127.0.0.1:27028/msm_full_flow_acceptance`、后端 3016 和 Next 8011 上完成真实注册登录、PDF／DOCX OSS 上传与签名解析、专项录音与文字作答、暂停刷新恢复、HR 对话、复盘与历史回看、明确 JD 的简历押题、跨账号读取拒绝及退出重登。无生产数据库、支付或部署操作。

- 录音由云端 TTS 生成虚构回答，作为 Chromium 虚拟麦克风输入；真实经过 MediaRecorder、WebM、后端转码和云端 ASR。录音识别结果保留了虚拟列表及 1.8 秒到 0.9 秒信息，校对确认前未发送。它不代表真人硬件麦克风或手机浏览器验收。
- 专项使用上传简历、未填写额外 JD，4 次作答后手动结束，复盘 89 分、4 条引用与原回答一致。HR 未选择简历或额外 JD，验证通用岗位路径，含反问和结束语共 4 次作答，2 道计分题，复盘 85 分。均只扣 1 次。
- 押题使用真实上传简历及合成前端 JD、15-25K 虚构薪资，生成 5 道题、匹配度 72；匹配度不是面试能力分。首次发现布局切换导致旧 SSE 中断、新恢复请求误报冲突；原任务已经成功保存，重放没有额外模型调用或扣次。修复后浏览器回归由失败转为通过，新账号真实首次押题直接成功。
- 修复将输入页确认改为只保存请求并导航，由生成页独占 SSE。回归入口 `apps/web/e2e/quiz-start.spec.ts`，不依赖真实模型或数据库；真实供应商复测与该 Mock 回归分别记录。

本轮两个测试账号、单一合成岗位和简历只是功能验收样本，不能据此证明评分标准化准确率、长时弱网能力或生产承载能力。完整问答、输入与截图另随验收报告交付；下文保留此前各轮的历史范围。

使用独立 MongoDB `127.0.0.1:27028/msm_live_acceptance`、合成账户及履历，经真实 Next HTTP/SSE 代理调用 Nest、DeepSeek Flash、Sambert 与 Paraformer。没有连接生产数据库或发布应用。语音由合成音频提供，不代表真人麦克风验收。

| 场景 | 作答数 | 已验证结果 |
| --- | --- | --- |
| 专业热身：含脚本偏题 | 6 | 正常结束、扣一次；首次报告失败，修复后原记录重试成功；报告指出偏题，未虚构总分 |
| HR 热身：协作及反问 | 4 | 正常结束、扣一次；问答原文、报告引用与原回答一致 |
| 专业补测：贡献、缓存与协作 | 6 | 正常结束、扣一次；报告如实指出固定回答与问题不匹配、依据不足 |

两类面试均验证：注册赠送、开场、真实语音合成及转写、校对后提交、多轮 SSE、同一回答重放不再次调用模型、暂停后重建后端并恢复、结束、报告生成，以及数据库中的回答数与扣次。热身规则允许提前结束，4 次作答并非漏存。

## 发现与修复

- 复盘首次调用耗尽 4000 输出 Token，全部属于 reasoning，未返回可解析 JSON。新增 `createAssessmentModel()` 明确禁用思考；已结束的原记录可直接重试，无需重跑面试。实际复盘耗时约 8～10 秒。
- 交互追问曾出现 20～26 秒等待。默认模型配置增加 `DEEPSEEK_THINKING_MODE=disabled`，稳定与创意模型继承该配置；保留显式开启开关。相似上下文的一次真实追问为 1.2 秒，这是单次抽样，不能视为 P95 或稳定时延承诺。
- 测试脚本早期关键词匹配错误导致多次偏题，后续收窄匹配。固定答案仍不等于真人自然回答，三场都不能作为专业评分准确性的正向基准；报告返回“信息不足”而非强凑总分属于正确边界。
- 合成语音中观察到“首屏→手屏”“空状态→控状态”等同音识别差异，因此保留校对步骤，不宣称识别完全准确。

两批完整链路的回调记录合计 16,019 输入 Token、21,114 输出 Token（包含首次失败及补测），另有一次独立快速追问抽样。实际费用和免费额度抵扣以供应商账单为准，没有读取到账单实扣。

## 复现入口与边界

`apps/server/test/integration/interview-live.cjs` 需编译产物、实际模型凭据、`NODE_ENV=test`、`RUN_INTERVIEW_LIVE=1` 和上述精确的独立数据库地址。`TEST_API_BASE` 只允许回环地址；代理验证需另启动指向本地 3016 的 Next 服务。每次最多两种场景、50 次模型创建，可通过 `LIVE_TYPES` 限定单一类型；`LIVE_RESUME=1` 只允许读取已结束场次的本地验证产物并重试报告。它会产生实际供应商用量，不进入默认测试或 CI。

本地 `pnpm check` 通过，新增模型工厂回归验证思考开关、复盘覆盖与预算传递。尚未验证真实简历 OSS（本地未配置）、真人手机录音、多岗位人工评分一致性、长时间负载或生产发布。

## 追问、复盘与文件解析补充验收

本轮使用人工编写的合成问答直接调用真实 Agent/AI Service，共 10 次模型创建；没有启动生产服务或连接数据库。前述完整 HTTP/SSE 验证与本轮服务级质量抽样是不同验证范围。

| 检查 | 结果与处理 |
| --- | --- |
| 相同协作回答，分别对应协作题和虚拟列表技术题 | 修复阶段裁判缺少问题上下文；修复后分别判断已回答、未回答，跑题不建议跳阶段。新增测试确认只取回答之前的对应提问 |
| 回答称首屏变快，但承认未固定网络和缓存 | 追问要求区分虚拟列表收益与接口耗时，并说明验证方式；未编造候选人的测量结果 |
| 两题较充分回答与跑题／缺乏测量依据的对照 | 初次两者总分均为 null，充分回答已有维度分仍被要求核验实际效果。修订评分说明后分别为 82、20；引用通过逐字匹配，真实语音流畅度仍为 null |
| 实际 PDF、DOCX 文件内容 | 合成文件均提取出岗位、项目和 1.8→0.9 秒描述。发现小型 PDF 的 Buffer 切片兼容问题，改用独立 Uint8Array 后通过；未替换或 Mock PDF／Word 解析库 |
| 文件简历进入面试 | 通过真实 InterviewService 开场解析回调，验证 resumeId 读取 PDF／DOCX 内容；编辑器快照优先且无需下载。数据库和网络用 Mock，不代表云端 E2E |
| 文件和权限失败 | 覆盖跨用户简历／URL、损坏文件、空文件、超限、403、404、下载超时、重定向以及未配置 OSS；保存元数据时只保留本人文件的无签名 HTTPS URL |

本轮检查命令：后端测试 `document-parser`、`interview-agent`、`interview-reliability`、`interview-report`、`sts.service`、`resume.service` 六组，以及后端 lint、build。PDF／DOCX 回归样本位于 `apps/server/test/interview/fixtures`，全部为生成的虚构英文简历，无个人数据。

边界：82／20 是两题合成样本的单次模型输出，不是人工标注基准或校准后的能力分；较充分回答中的索引边界描述仍可追问，模型反馈对技术细节的判断不保证全部准确。按用户要求，本轮仅验收本地解析和错误处理；未配置 OSS 测试环境，故真实上传、Bucket CORS／RAM 和私有文件云端读取仍未验收。未增加 OCR，扫描件、加密或损坏文件不能保证提取。

## 面试流式与语音稳定性升级

- 专业考察改为真实增量生成，固定模板立即发送。真实图节点配合受控 SDK 流，经 Next SSE 代理验证：模型未完成时首段已到客户端连接；保存前没有 waiting，保存后完整题目、版本和重放保持一致。原 Mongo／JWT／并发／重试／恢复回归同时通过。
- 回合 90 秒超时会向图、摘要、裁判和模型传递取消信号；取消后丢弃已缓冲 token。忽略取消的供应商仍受旧任务租约和 active 标记限制。断线后仍可恢复已保存回合，不把浏览器关流当作撤销业务。
- 云端朗读播放当前句时最多预取下一句，消费顺序不变。停止、静音、换账户、录音或离开会取消预取，迟到音频不进入下一题；预取失败先保留当前句，到失败句时提示重听。提前停止时，已开始预取的一句可能产生用量。空闲试听组件卸载不会取消另一组件的浏览器朗读。
- Chromium 在 390／1440px 下用本地合成 WAV 验证真实媒体播放、首句结束前已发起下一句请求、再次试听失败提示及无横向溢出；供应商接口在该浏览器测试中为 Mock。
- 另用合成履历直接调用真实 DeepSeek 两次：一次完整生成，首段约 622ms、完成约 975ms；一次首段后取消，生成器约 2ms 停止返回。这是单次服务级抽样，不能视为端到端 P95 或供应商停止计费的保证。
- 移除直接执行候选人代码的本机 Node 子进程及图工具节点。当前代码题仅静态分析，不能声称已运行测试；恢复运行能力需另行提供隔离环境。

复现入口：`test/interview/interview-agent.spec.ts`、`interview-turn.spec.ts`、前端 `test/interview/cloud-speech.spec.tsx`／`speech-synthesis.spec.tsx`，以及 `test/integration/turn-recovery.cjs` 和 `e2e/speech-playback.spec.ts`。代理集成使用专用 `msm_phase1` 数据库和 `TEST_PROXY_BASE` 指向测试 Next；浏览器用例无需数据库。未验证真人弱网长时间语音，未接入实时双工框架或生产部署。

本轮全量单元测试曾出现一次本地 DashScope WebSocket 模拟服务握手异常（两项用例失败），定向复跑及随后全量复跑均通过，未改动供应商凭据或断言来绕过；偶发原因未确认。
